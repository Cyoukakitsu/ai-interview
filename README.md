# ai-interview

面向日本**中途採用**求職者的 AI 面接対策エージェント（开源・自行部署）。

求職者上传職務経歴書，Agent 生成**想定問答集**（预测的面试问题 + 基于真实经历的回答草稿），之后再结合応募先企業的求人票与公开信息，生成企業別問答。所有输出均为日语。

> 当前状态：**设计阶段**，尚无代码。术语定义见 [CONTEXT.md](./CONTEXT.md)。

## 路线图

| 阶段 | 内容 |
|---|---|
| **功能① 第一步（MVP）** | 上传職務経歴書 → 生成共通問答（標準質問 + 深掘り質問） |
| 功能① 第二步 | 提供求人票 URL → Agent 搜索公司公开信息 → 生成企業別問答（含志望動機、逆質問） |
| 功能① 第三步 | 企業情報ストック：按公司积累资料并复用；资料超出上下文时引入 RAG（pgvector） |
| 功能② | 職務経歴書ヒアリング：没有職務経歴書的求職者，由 Agent 多轮提问后代写 |
| 功能③ | 模擬面接：语音模拟面试（先做简易版，再考虑实时对话） |

## 产品规则

- **绝不编造**：每条回答必须附带根拠（材料原文片段），后端用字符串匹配校验根拠是否真实存在；信息不足时标为**要確認**并向求職者追问。
- **先写后问**：先生成能写的部分，缺信息的条目标为要確認，求職者在该条下回答后由 Agent 补全。
- **可修改**：每条想定問答都可以手动编辑、对单条下指令让 Agent 改写，求職者也可自行追加问题。
- **職務経歴書更新**：Agent 对比新旧版本，只对受影响的条目提出**修正提案**，由求職者逐条采纳；不会自动覆盖。
- **共通問答复用**：每个求職者只有一份，投递多家公司时共用；企業別問答每家公司各一份。
- **材料**：職務経歴書必需（PDF / Word，或粘贴文本）；不处理履歴書；不保存原始文件，只保存解析后的文本；扫描版 PDF 提示改为粘贴文本。
- **求人票**：以 URL 提供，抓取失败时改为粘贴文本；抓取成功时保存快照。
- **信息来源**：只用公开的官方/半官方信息和求職者自己上传的笔记；**不抓取** OpenWork、転職会議 等口コミ/体験談网站。
- **导出**：Markdown + PDF（浏览器打印）。
- 回答的文体与长度：待根据面试资料设计系统提示词时确定。

## 技术方案

| 部分 | 选择 |
|---|---|
| 仓库 | 单仓库，pnpm workspace：`apps/web`、`apps/api`、`packages/shared` |
| 前端 | Next.js（App Router）+ Tailwind CSS + shadcn/ui + TanStack Query；直接调用 NestJS，不写 API Route |
| 后端 | NestJS（模块化单体）+ Prisma + PostgreSQL |
| 生成任务 | BullMQ（Redis）后台任务队列，worker 与 API 同进程，进度通过 SSE 推送 |
| 大模型 | 多厂商 SDK：主流厂商原生接入，其他走 OpenAI 兼容接口（Ollama 等）；Key 与可选模型写在 `.env`，界面下拉选择一个全局模型；每次生成记录所用模型 |
| Agent | 只用 SDK 的工具调用循环，流程自己写；暂不使用 LangChain / LangGraph 等框架 |
| 输出格式 | 结构化输出，schema 用 zod 定义并放在 `packages/shared` 中共用；Markdown 只在导出时生成 |
| 解析 | 后端用解析库把 PDF / Word 转为文本 |
| RAG | 第一、二步不使用；第三步按需引入 pgvector |
| 质量评测 | 3～5 份**虚构**職務経歴書作为 eval 样本，检查根拠校验、要確認标记、標準質問覆盖率 |
| 部署 | `docker-compose.yml` 一键启动 + `.env.example` |
| 用户 | MVP 单用户、无登录；数据模型从一开始就以求職者为单位 |
